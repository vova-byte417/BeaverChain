# BeaverChain 用户体验设计原则

**文档版本**: v1.0  
**创建日期**: 2026-05-12  
**设计风格**: Linear.app 极简风格

---

## 1. 设计理念与核心原则

### 1.1 设计愿景

> **打造让 AI 开发者感到愉悦和高效的产品体验，让复杂的大模型构建变得简单直观。**

### 1.2 三大核心原则

#### 原则一：极简高效 (Simplicity & Efficiency)

**设计信念**：少即是多。去除一切不必要的元素，让用户专注于真正重要的事情。

**具体要求**：
- ✅ **信息层级清晰**：3 秒内识别页面主体，30 秒理解全部内容
- ✅ **操作路径最短**：核心功能不超过 3 步完成
- ✅ **视觉降噪**：每个页面的主色调不超过 3 种
- ✅ **键盘优先**：所有常用操作支持快捷键
- ❌ **禁止**：多余的装饰、闪烁动画、无关的推荐内容

#### 原则二：精确专业 (Precision & Professional)

**设计信念**：开发者工具应该像精密仪器一样准确可靠。

**具体要求**：
- ✅ **像素级对齐**：所有元素严格对齐 4px 网格
- ✅ **一致的视觉语言**：相同功能在任何地方表现一致
- ✅ **数据可视化准确**：图表无截断、无变形、比例正确
- ✅ **状态反馈精确**：加载、成功、错误状态清晰可辨
- ❌ **禁止**：模糊的图标、不一致的间距、随意的颜色

#### 原则三：可预测可靠 (Predictability & Reliability)

**设计信念**：用户应该永远知道接下来会发生什么，系统应该永远可靠。

**具体要求**：
- ✅ **操作结果可预测**：按钮文案明确告诉用户会发生什么
- ✅ **状态反馈及时**：用户操作后 100ms 内必有视觉反馈
- ✅ **错误处理友好**：告诉用户发生了什么、为什么、怎么办
- ✅ **支持撤销重做**：所有破坏性操作支持撤销
- ❌ **禁止**：静默失败、意外的破坏性操作、模糊的错误提示

## 2. 视觉设计系统

### 2.1 颜色方案

> 基于 Linear.app 风格调整，适配 AI 平台属性

#### 主色调

| 用途 | 色值 | 十六进制 | 使用场景 |
|------|------|---------|---------|
| **品牌主色** | 深紫色 | `#5E6AD2` | Logo、主按钮、关键强调 |
| **交互强调色** | 亮紫色 | `#8A8F98` | 悬停状态、链接、辅助强调 |
| **成功色** | 深绿 | `#2ECC71` | 成功状态、正增长 |
| **警告色** | 橙色 | `#F39C12` | 警告、需要注意 |
| **错误色** | 红色 | `#E74C3C` | 错误、失败、负增长 |
| **信息色** | 蓝色 | `#3498DB` | 信息提示、中性状态 |

#### 中性色阶（11 级灰度）

```
#FFFFFF (白)
  ↓
#FAFAFA → 页面背景
#F5F5F5 → 卡片背景
#E8E8E8 → 边框（轻）
#D9D9D9 → 边框（常规）
#BFBFBF → 禁用状态
#8C8C8C → 辅助文本
#595959 → 次要文本
#262626 → 主要文本
#1A1A1A → 标题文本
  ↓
#000000 (黑)
```

**使用规范**：
- 正文：`#262626` (dark) / `#E8E8E8` (light)
- 辅助说明：`#8C8C8C`
- 边框：`#E8E8E8`（轻）、`#D9D9D9`（重）
- 背景分层：白色卡片 → `#FAFAFA` 页面背景 → 深色导航栏

#### 深色模式

未来支持，第一阶段优先确保浅色模式完美。

### 2.2 字体排版系统

#### 字体家族

```
- 首选：Inter (现代无衬线，专为屏幕设计)
- 备选：-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto
- 代码：JetBrains Mono, Menlo, Monaco, "Courier New"
```

#### 字号层级（7 级）

| 级别 | 字号 | 行高 | 字重 | 用途 |
|------|------|------|------|------|
| **H1** | 32px | 40px | 600 | 页面大标题 |
| **H2** | 24px | 32px | 600 | 区块标题 |
| **H3** | 20px | 28px | 500 | 卡片标题 |
| **H4** | 18px | 26px | 500 | 小标题 |
| **Body-L** | 16px | 24px | 400 | 正文、表单 |
| **Body-M** | 14px | 20px | 400 | 辅助文本 |
| **Body-S** | 12px | 16px | 400 | 标签、说明 |

#### 字重使用规范

- **400 (Regular)**：常规正文、辅助文本
- **500 (Medium)**：按钮、小标题、需要强调的文本
- **600 (Semibold)**：标题、重要数据
- ❌ 禁止使用 700+ 粗体（除特殊营销场景外）

### 2.3 间距系统

**基础单位：4px**

```
4px   → 元素内边距微调
8px   → 紧凑间距
12px  → 标准内边距
16px  → 元素间距
20px  → 组件间距
24px  → 区块间距
32px  → 大区块间距
48px  → 页面级间距
```

**应用示例**：
- 按钮内边距：`12px 20px`
- 卡片内边距：`20px`
- 列表项间距：`12px`
- 表单字段间距：`16px`
- 页面区块间距：`32px`

### 2.4 圆角系统

| 尺寸 | 半径 | 用途 |
|------|------|------|
| **无圆角** | 0px | 分割线、进度条 |
| **小圆角** | 4px | 小按钮、标签、复选框 |
| **中圆角** | 6px | 按钮、输入框、小卡片 |
| **大圆角** | 8px | 卡片、弹窗、下拉菜单 |
| **超大圆角** | 12px | 大卡片、特色区块 |

### 2.5 阴影系统

| 层级 | 阴影值 | 用途 |
|------|--------|------|
| **Level 0** | 无阴影 | 平面元素 |
| **Level 1** | `0 1px 2px rgba(0,0,0,0.04)` | 轻微悬浮（按钮悬停） |
| **Level 2** | `0 2px 8px rgba(0,0,0,0.06)` | 卡片、输入框聚焦 |
| **Level 3** | `0 4px 16px rgba(0,0,0,0.08)` | 悬浮卡片、下拉 |
| **Level 4** | `0 8px 32px rgba(0,0,0,0.1)` | 弹窗、抽屉 |

## 3. 交互设计规范

### 3.1 通用交互模式

#### 加载状态

**原则**：优先使用局部加载，避免全屏加载打断用户流。

**实现方式**：
- 按钮内加载：按钮文字替换为 spinner
- 卡片内加载：骨架屏 (Skeleton)
- 列表加载：底部加载指示器
- 仅首次页面加载：顶部细进度条

**禁止**：
- ❌ 全屏 spinner 遮罩
- ❌ 超过 3 秒无任何反馈
- ❌ 假进度条（胡乱跳动的）

#### 空状态

**设计要求**：
- ✅ 友好的插图 + 清晰的标题
- ✅ 告诉用户"为什么是空的"
- ✅ 告诉用户"接下来可以做什么"
- ✅ 提供明确的行动按钮

**示例（模型列表为空）**：
> 📭 还没有模型版本
> 
> 创建你的第一个模型版本，开始管理大模型的完整生命周期。
> 
> [ 创建版本 ]

#### 错误状态

**错误信息三要素**：
1. **发生了什么**：简洁明了的错误标题
2. **为什么发生**：技术原因（可选，放在折叠面板中）
3. **该怎么办**：具体的恢复操作

**好的错误提示**：
> ❌ 版本创建失败
> 
> 存储空间不足，请清理不需要的模型文件后重试。
> 
> [ 查看存储空间 ]  [ 重试 ]

**坏的错误提示**（避免）：
> 操作失败。错误码：500。

#### 确认对话框

**破坏性操作必须二次确认**：
- 删除版本、删除项目、撤销部署等
- 明确显示操作后果
- 提供"取消"和"确认"两个按钮
- "确认"按钮使用危险色（红色）

**文案要求**：
- 标题：问句形式，如"确定要删除这个模型版本吗？"
- 正文：说明不可逆后果
- 按钮："取消"（默认聚焦）、"删除"（红色）

### 3.2 表单设计

#### 输入框

| 状态 | 视觉表现 |
|------|---------|
| **默认** | 灰色边框，浅灰占位符 |
| **聚焦** | 品牌色边框 + 2px 阴影 |
| **填写中** | 品牌色边框 |
| **填写正确** | 绿色边框 + 对勾图标 |
| **填写错误** | 红色边框 + 错误提示 |
| **禁用** | 浅灰背景，不可点击 |

#### 表单布局

**单列为主**：
- 标签在输入框上方
- 标签左对齐
- 错误提示在输入框下方
- 相关字段分组，组间间距更大

**分组示例**：
```
┌─────────────────────────────────┐
│  基本信息                       │
│  [ 名称        ]                │
│  [ 描述        ]                │
├─────────────────────────────────┤
│  模型配置                       │
│  [ 模型类型    ]                │
│  [ 权重文件    ]                │
└─────────────────────────────────┘
```

#### 表单验证

- **实时验证**：失去焦点时立即验证
- **输入提示**：开始输入前就显示格式要求
- **渐进式披露**：复杂格式的示例，点击"查看格式"才显示

### 3.3 列表与表格设计

#### 数据表格原则

1. **信息密度适中**：行高 40-48px，避免过于拥挤或松散
2. **列宽合理**：固定列 + 自适应列混合
3. **对齐正确**：
   - 文本：左对齐
   - 数字：右对齐
   - 状态标签：居中对齐
4. **操作列**：固定在右侧，常用操作直接显示，次要操作放"更多"

#### 列表交互

- **悬停效果**：行背景轻微加深 + 显示操作按钮
- **选中状态**：左侧边框高亮 + 背景色
- **加载更多**：滚动到底部自动加载，或点击"加载更多"按钮
- **空搜索**：友好提示 + 清除搜索按钮

### 4.2 导航设计

#### 顶部导航栏

- 高度：56px
- 左侧：Logo + 产品名
- 右侧：全局搜索 → 通知 → 用户头像
- 固定在顶部，滚动时不消失

- 宽度：240px
- 可折叠（折叠后 64px，仅显示图标）
- 菜单项：图标 + 文字（折叠后仅图标）

**结构**：
> 首页 > 模块名 > 页面名 > 详情名

**要求**：
- 所有层级都可点击返回
- 当前页面不可点击（无下划线）
- 超过 4 级时中间省略

## 6. 可访问性 (A11y)

### 6.1 颜色对比度

- 正文文本：对比度 ≥ 4.5:1 (WCAG AA)
- 大文本（>18px）：对比度 ≥ 3:1
- 使用工具验证：https://webaim.org/resources/contrastchecker/

### 6.2 键盘导航

- 所有交互元素可通过 Tab 聚焦
- Tab 顺序符合视觉顺序
- 聚焦状态清晰可见（2px 品牌色外框）
- Enter/Space 触发按钮点击
- Esc 关闭弹窗、取消操作

### 6.3 屏幕阅读器支持

- 所有图片有 alt 文本
- 图标按钮有 aria-label
- 表单字段有正确的 label 关联
- 动态内容变化有 aria-live 区域播报
- 语义化 HTML（nav, main, section, article, button, etc.）

## 7. 性能体验指标

### 7.1 前端性能目标

| 指标 | 目标值 | 测量方式 |
|------|--------|---------|
| **LCP** (最大内容绘制) | < 2.5s | Lighthouse |
| **FID** (首次输入延迟) | < 100ms | 真实用户监控 |
| **CLS** (累计布局偏移) | < 0.1 | Lighthouse |
| **FCP** (首次内容绘制) | < 1.5s | Lighthouse |
| **TTI** (可交互时间) | < 3.5s | Lighthouse |

### 7.2 交互响应时间

| 操作类型 | 响应时间目标 |
|---------|-------------|
| 按钮点击反馈 | < 100ms |
| 页面切换 | < 500ms |
| 表单提交（简单） | < 1s |
| 列表加载 | < 2s |
| 异步操作（如部署） | 1s 内显示进度 |
